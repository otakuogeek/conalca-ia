================================================================================
  2. ESTRUCTURA DEL JSON - CAMPOS DISPONIBLES
================================================================================

{
  "user_id":        (OBLIGATORIO) ID del usuario asignado al grupo.
                    Tipo: integer
                    Ejemplo: 13
                    Usuarios disponibles:
                      - 13 = Don David Navarro
                      - 11 = EDGARDO GALAN VELAZQUES

  "client_id":      (OPCIONAL) ID de un cliente ya existente en el sistema.
                    Tipo: integer
                    Ejemplo: 1
                    Si no se envía, se puede usar "client_name" para buscar
                    por nombre, o crear un cliente nuevo con "client".

  "client_name":    (OPCIONAL) Nombre del cliente para buscar en base de datos.
                    Si no se conoce el client_id, envíe el nombre y el sistema
                    buscará automáticamente en la tabla de clientes.
                    Tipo: string, máx 255
                    Ejemplo: "ECOPETROL"
                    NOTA: La búsqueda es por coincidencia parcial (LIKE),
                    así que "ECOPETROL" encontrará "ECOPETROL S.A."
                    
                    Prioridad de resolución del cliente:
                      1. client_id (si viene, se usa directo)
                      2. client_name (si no viene client_id, busca por nombre)
                      3. client (si no encuentra por nombre, crea uno nuevo)
                      4. Fallback: usa el primer cliente disponible en BD

  "client":         (OPCIONAL) Datos para crear un cliente nuevo.
                    Solo se usa si NO se envía "client_id" ni "client_name".
                    Tipo: objeto
                    Campos:
                      "nombre":     Razón social de la empresa (string, máx 255)
                      "documento":  NIT o documento (string, máx 50)
                      "telefono":   Teléfono de contacto (string, máx 50)
                      "direccion":  Dirección física (string, máx 255)
                      "ciudad":     Ciudad (string, máx 100)

  "reference":      (OPCIONAL) Referencia única del grupo.
                    Tipo: string, máx 255
                    Default: "TEST-SEED-" + fecha/hora
                    Ejemplo: "PRUEBA-CARGA-001"

  "operation_type": (OPCIONAL) Tipo de operación logística.
                    Tipo: string
                    Valores permitidos: "DISTRIBUCION", "EXPORTACION", "IMPORTACION"
                    Default: "DISTRIBUCION"

  "cargo_type":     (OPCIONAL) Tipo de carga general.
                    Tipo: string
                    Ejemplo: "Carga seca"

  "type":           (OPCIONAL) Tipo de grupo.
                    Tipo: string
                    Default: "Cotización"

  "rutas":          (OBLIGATORIO) Array de rutas/cotizaciones. Mínimo 1.
                    Tipo: array de objetos
                    Cada ruta tiene los siguientes campos:

    ┌─────────────────────────┬────────────┬──────────────────┬──────────────────────────────┐
    │ CAMPO                   │ OBLIGAT.   │ DEFAULT          │ DESCRIPCIÓN                  │
    ├─────────────────────────┼────────────┼──────────────────┼──────────────────────────────┤
    │ ciudad_origen           │ SÍ         │ -                │ Ciudad de origen             │
    │ ciudad_destino          │ SÍ         │ -                │ Ciudad de destino            │
    │ valor                   │ SÍ         │ -                │ Precio cotización (numérico) │
    │ flete                   │ NO         │ null             │ Flete ofrecido al conductor  │
    │ tipo_mercancia          │ NO         │ "Carga general"  │ Tipo de mercancía            │
    │ tipo_producto           │ NO         │ null             │ Producto específico          │
    │ peso_mercancia          │ NO         │ null             │ Peso en kg (string)          │
    │ dimensiones_exactas     │ NO         │ null             │ Dimensiones (ej: "12x2.5x3") │
    │ cantidad                │ NO         │ "1"              │ Cantidad de unidades         │
    │ cantidad_vh             │ NO         │ "1"              │ Cantidad de vehículos        │
    │ tipo_embajale           │ NO         │ null             │ Tipo de embalaje             │
    │ tipo_carroceria         │ NO         │ null             │ Tipo carrocería del vehículo │
    │ vehiculo_requerido      │ NO         │ "TRACTOCAMION"   │ Clase de vehículo requerido  │
    │ valor_declarado         │ NO         │ null             │ Valor declarado de mercancía │
    │ seguro                  │ NO         │ "No"             │ Requiere seguro ("Si"/"No")  │
    │ temperatura_mercancia   │ NO         │ "No aplica"      │ Temperatura requerida        │
    │ registro_fotografico    │ NO         │ null             │ Requiere registro fotográfico│
    │ fecha                   │ NO         │ null             │ Fecha de la ruta (YYYY-MM-DD)│
    │ fecha_cargue            │ NO         │ null             │ Fecha y hora de cargue       │
    │                         │            │                  │ Formato: "YYYY-MM-DD HH:MM"  │
    │                         │            │                  │ Ejemplo: "2026-04-28 08:00"  │
    │                         │            │                  │ Se guarda en:                │
    │                         │            │                  │ cotizacion_models.           │
    │                         │            │                  │   fecha_hora_descargue_cargue│
    │                         │            │                  │ La IA informa al conductor   │
    │                         │            │                  │ fecha y hora si lo pregunta  │    │ porcentaje              │ NO         │ 0                │ Porcentaje adicional         │
    └─────────────────────────┴────────────┴──────────────────┴──────────────────────────────┘

  NOTA IMPORTANTE sobre "valor" vs "flete":
  ─────────────────────────────────────────
  • valor:  Precio de la cotización (lo que se cobra al cliente).
  • flete:  Valor del flete ofrecido al conductor en la llamada.
            Si se envía "flete", la IA usará ese monto al negociar con el
            conductor. Si NO se envía, la IA usará "valor" como fallback.

  7. FLUJO DE USO RECOMENDADO
================================================================================

  1. Enviar POST /api/test/seed-cotizacion con los datos de la carga.
  2. Anotar el "group_id" y "cotizacion.id" de la respuesta.
  3. Ir al tablero Kanban: https://conalcaia.conalca.com.co/cotizacion
  4. Buscar la tarjeta en la columna "En tránsito".
  5. Hacer clic en el icono de camión (🚚) para abrir el detalle.
  6. En la sección CONDUCTORES, hacer clic en "Registrar Llamadas".
  7. Esto buscará conductores disponibles vía Arcángel.
  8. Luego se pueden iniciar las llamadas con ElevenLabs.

================================================================================
  9. NOTAS IMPORTANTES
================================================================================

  - Este endpoint NO requiere autenticación (es para pruebas).
  - Los grupos se crean directamente en estado "En tránsito" con
    decisión del cliente "aceptada" para que funcione todo el flujo.
  - Los grupos creados con referencia automática (TEST-SEED-*) se
    pueden listar y limpiar fácilmente sin afectar datos reales.
  - Si se envía "client_id" y "client" al mismo tiempo, se usa
    "client_id" y se ignora "client".
  - NUEVO: Se puede enviar "client_name" en lugar de "client_id".
    El sistema buscará automáticamente el cliente por nombre en la BD.
    Prioridad: client_id > client_name > client (crear nuevo) > fallback.
  - El campo "valor" es el precio total de la cotización para esa ruta.
  - Se pueden enviar hasta 20 grupos en un solo request con /seed-multiple.

  ENDPOINT SAVE-QUOTE-FROM-CHAT:
  - POST /api/save-quote-from-chat también soporta "client_name".
  - Si no se envía "client_id", se puede enviar "client_name" y el
    sistema resolverá el ID automáticamente buscando por nombre.
  - Si no encuentra coincidencia, retorna error 422 con mensaje claro.
